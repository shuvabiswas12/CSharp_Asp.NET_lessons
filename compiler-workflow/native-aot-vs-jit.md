# Understanding .NET App Execution and Native AOT Compilation

This document explains what happens when you **build** and **run** a .NET application,
covering the role of different compilers and how **JIT** and **Native AOT** work.

---

## 1. Normal .NET App Execution (JIT Compilation)

### Build Time
- **Compiler:** Roslyn (csc.exe)
- **Action:** `.cs` files → compiled into **IL (Intermediate Language)** code + **metadata**
- **Output:** `.dll` or `.exe` containing IL and method metadata (type info, method signatures, attributes)

### Runtime
1. **CLR Loader** reads IL and prepares metadata ("Method IL ready for JIT")
2. **RyuJIT Compiler** compiles each method **on-demand** the first time it's called ("methods compiled **only when needed**")
3. **CPU** executes the native code generated by JIT
4. Compiled method are cached in the memory.

Example:
- `Main()` is compiled immediately.
- If a method `Calculate()` is never called, it is **never JIT-compiled**.

**Flow Diagram:**
```
.cs → [Roslyn] → IL → [dotnet.exe loads CLR] → [RyuJIT compiles on demand] → Native code → CPU
```

**Advantages:**
- Platform independent
- Flexible runtime capabilities

**Disadvantages:**
- Slower startup (due to JIT work at runtime)
- Extra runtime dependency

---

## 2. Native AOT (Ahead-of-Time) Compilation

### Build Time
1. **Roslyn** compiles `.cs` files → IL
2. **ILLink (Trimmer)** removes unused IL to reduce size
3. **Native AOT Compiler** converts IL to native CPU code for the target OS/CPU
4. Bundles runtime and dependencies into a **self-contained native executable**

### Runtime
- OS loads the native executable (For example, .exe on Windows, no extension on Linux/macOS)
- CPU executes directly (no JIT required at runtime)

**Flow Diagram:**
```
.cs → [Roslyn] → IL → [ILLink trims] → [NativeAOT compiler] → Native EXE → CPU
```

**Advantages:**
- Fast startup
- No runtime dependency
- Easier distribution

**Disadvantages:**
- Platform-specific build
- Limited reflection and dynamic code generation
- Larger binary sizes compared to trimmed IL builds

---

## 📝 Key Terms

- **Method IL ready for JIT:** Method's IL is loaded in memory, metadata prepared, waiting for JIT compilation.

- **Methods compiled on-demand:** The JIT compiles methods only when they're called for the first time. Methods that are never called are never compiled into native code

- **IL:** It is CPU-independent bytecode produced by the C# compiler (Roslyn) and stored in assemblies (`.dll`/`.exe`)

---

## 📌 CLI Example for Native AOT Publish

```bash
dotnet publish -c Release -r win-x64 /p:PublishAot=true
```

**Typical .csproj configuration:**
```xml
<PropertyGroup>
    <PublishAot>true</PublishAot>
    <RuntimeIdentifier>win-x64</RuntimeIdentifier>
    <SelfContained>true</SelfContained>
</PropertyGroup>
```

---

## 📌 Visual Studio Steps to Enable Native AOT
1. Right-click project → **Publish…**
2. Select or create a publish profile
3. Click **Settings** (gear icon)
4. Enable **"Native AOT publish"**
5. Save changes

---

## 📌 Quick Look: How .NET Code Runs
| Step              | What Happens                                                                    | Input       | Output                                                     |
| ----------------- | ------------------------------------------------------------------------------- | ----------- | ---------------------------------------------------------- |
| **Build**         | Roslyn compiler turns your C# code into intermediate language (IL) and metadata | `.cs` files | IL + Metadata (`.dll` / `.exe`)                            |
| **Run (JIT)**     | CLR loads IL and RyuJIT compiles methods on-demand into native code             | IL          | Native Machine Code                                        |
| **Publish (AOT)** | NativeAOT compiles IL ahead of time into a platform-specific executable         | IL          | Native Executable (`.exe` on Windows, none on Linux/macOS) |

---

## 📌 Long Story Short
- **JIT Mode:** Compile at runtime → flexible, portable, but slower startup
- **Native AOT Mode:** Compile ahead of time → fast startup, self-contained, but less dynamic
